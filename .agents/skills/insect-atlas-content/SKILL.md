# Insect Atlas 콘텐츠 작업

프로젝트 루트의 [AGENTS.md](../../../AGENTS.md)와 [README 개발 안내](../../../README.md#개발-안내)를 기준으로 작업한다. 아래 코드 경로는 프로젝트 루트 기준이다.

## 변경 대상을 좁힌다

종 ID, 변경할 설명 또는 이미지 역할, 관련 배치와 근거를 확인한다. 이미지 승격이 포함되면 형태 검수 결과와 공개할 범위를 확인한다. 요청이 이미 구현되어 있는지 먼저 확인한다. 필요한 대상 정보가 없으면 그 정보만 질문하고 독립적인 조사는 계속한다.

## 실제 데이터 연결을 따른다

- `data/insects.js`의 해당 종과 `record()`를 찾는다. `options.gallery`, 기존 갤러리 공급자, `withLifeStages()`, `galleryAdditions()` 중 실제 경로만 추적한다.
- 새 종은 `data/child-content.js`의 `specific` 항목을 함께 등록한다. `childContentFor()`는 종별 본문을 요구하며 검증기는 종 ID와 본문의 1:1 대응을 확인한다.
- 어린이 설명의 출처에는 실제 근거와 확인일을 기록하고 기존 출처 형식을 재사용한다.
- 이미지 순서를 바꾸면 `app.js`의 호출부에서 대표 이미지 선택과 상세 표시 순서를 확인한다.
- 생물학적 생활사는 근거에 따라 정한다. 기존 검증기의 배치별 이미지 수에 맞추려고 분류를 바꾸거나 요청되지 않은 그림을 추가하지 않는다.

## 이미지와 검수 기록을 함께 관리한다

- 기존 갤러리 항목의 실제 필드 형식을 재사용한다. 과거 초안인 `data/insect-schema.js`를 그대로 복사하지 않는다.
- 이미지를 생성하는 작업에는 사용 가능한 이미지 생성 스킬을 적용한다. 프로젝트에 별도의 자산 생성 명령이 있다고 가정하지 않는다.
- 원본과 생성·검수 근거를 보존한다. 교체 전 파일명과 종 ID의 참조를 검색하고, 새 버전 경로를 사용하면 데이터·매니페스트·고정 경로 검사도 함께 확인한다.
- 새 자산의 승격은 AGENTS.md의 형태·출처 검수 원칙을 따른다. 기존 임시 공개 상태와 예외의 해석은 [README 공개·검수 안내](../../../README.md#공개와-검수)를 확인한다. 과거 예외를 새 배치에 자동 적용하지 않는다.

## 검수 화면 연결을 확인한다

`review.js`의 `manifestUrls`와 `recordsForManifest()`를 함께 확인한다. 지원 형식과 브라우저 판정의 저장 범위는 README의 공개·검수 안내를 따른다.

새 배치를 연결할 때 기존 자료 형식을 보존하면서 필요한 변환만 구현한다. 파일을 목록에 추가한 것만 확인하지 말고, 이미지별 `asset`을 가진 실제 항목이 만들어지는지 확인한다. 공개에 반영할 판정은 대상 이미지 경로와 근거를 프로젝트 검수 기록에 남기고 공개 데이터와 대조한다.

## 최소 검증과 완료

프로젝트 루트에서 `node scripts/verify.mjs`를 실행한다.

- 검사 실패가 변경 때문인지 기존 상태 때문인지 구분한다. 종수·배치·생활사·파일명의 고정 조건은 실제 승인된 변경에 필요한 부분만 갱신한다. 통과를 위해 검증 조건을 제거하지 않는다.
- 변경한 검수본과 공개본의 동일성을 확인한다. 기존 검사는 모든 이미지 쌍을 비교하지 않으므로 필요하면 PowerShell `Get-FileHash -Algorithm SHA256`으로 두 파일을 비교한다.
- 종·이미지 변경은 실제 검색·상세·갤러리에서 확인한다. 검수 화면을 변경했다면 대상 항목의 표시와 판정 저장 범위도 확인한다.
- 완료 보고에는 변경한 종·이미지, 공개·검수 상태, 실행한 검증 결과와 미확인 사항을 구분한다. 기본 검사만으로 형태의 정확성이나 사용자 최종 승인을 주장하지 않는다. 커밋·배포 범위는 AGENTS.md와 현재 사용자 지시를 따른다.
